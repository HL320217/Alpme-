# Alpme 注册控制台（学习用）

一个用于**学习 HTTP 协议分析与自动化流程**的示例项目：协议级注册、代理池管理、实时执行日志、登录态复用与兑换码兑换，全部带一个本地 Web 控制台。

> ⚠️ **本项目仅供学习与技术研究（HTTP 抓包分析、接口调用、前端可视化）。请勿用于批量注册他人服务、刷量、绕过风控或任何违反目标站点服务条款的用途。使用前请阅读文末完整的[免责声明](#免责声明)。**

## 它是什么 / 不是什么

**是**：一个把「网页上点几下」变成「脚本发一个请求」的教学案例。你能从中学到：

- 如何从页面的 JS chunk 里找出真实的提交接口与字段名
- 如何用标准库（`urllib`）发 POST、读 `Set-Cookie`、复用 JWT 登录态
- 如何做代理池的可用性校验、轮换与失效剔除
- 如何用 `http.server` 写一个零依赖的本地控制台

**不是**：

- 不是一个通用的「注册机框架」，代码里的接口、字段、路径都是针对某一个具体站点写的
- 不提供任何账号、代理、Token 或绕过验证码的能力
- 不保证目标站点当前或未来仍然可用（站点改版即失效）

## 功能

| 模块 | 能力 |
|---|---|
| 注册 | 随机邮箱（`@qq.com` 纯数字 / `@gmail.com`）、随机姓名、随机 12 位密码 |
| 执行日志 | 一次注册拆成 9 步，含累计耗时、HTTP 状态、响应体、失败原因 |
| 代理池 | 添加即校验、全部复检、清空、逐个移除、按「用得最少」轮换、连续限流自动下线 |
| 限流退避 | 命中限流后按 1×/2×/4×… 倍增等待（可开关、可设上限） |
| 登录态 | 注册成功自动抓 `Set-Cookie`，供后续需要登录的操作复用 |
| 兑换码 | 批量兑换、单个兑换、注册成功后自动兑换，并读取兑换后的套餐 |
| 账号管理 | 列表、搜索、单条复制、复制全部、下载 TXT |

## 快速开始

```bash
git clone <your-repo-url>
cd alpme

python alpme_panel.py
```

浏览器打开 <http://127.0.0.1:8080>，默认停在「注册」页。

常用参数：

```bash
python alpme_panel.py --port 9090
```

仓库里还有一份**早期单文件版本** `alpme_register.py`（命令行参数驱动 + 自带仪表盘），适合对照阅读：

```bash
python alpme_register.py -n 20 -c 5          # 注册 20 个，并发 5
python alpme_register.py -n 0 -c 10          # 不限数量，网页点「停止」或 Ctrl+C
python alpme_register.py --port 9090
```

## 三个页面

### ① 注册 `/register`

- 设置 **注册数量**（0 = 不限）、**并发**
- 「开始注册」/「停止」，「清空日志」
- 顶部统计：注册目标 / 成功 / 失败 / 总请求 / 成功率 / 平均耗时 / 限流次数
- 执行日志：每行一次尝试，可勾选「显示每一步」展开 9 步明细

一次尝试的日志长这样：

```
15:41:02 [限流] 773496@qq.com / Alex Johnson / J5enevb2lgjS   950ms · HTTP 403
   1/9 生成账号      773496@qq.com / Alex Johnson / 密码 12 位
   2/9 组装请求体    123 字节 · 字段 email+password+name+ref+promo+captcha
   3/9 选择出口      本机 IP（未配置代理）
   4/9 建立连接      直连 TLS 握手
   5/9 收到响应      HTTP 403 · 响应体 95 字节
   6/9 解析响应      {"error": "Too many accounts have already been registered..."}
   7/9 判定结果      限流 · Too many accounts...
   9/9 完成          总耗时 950 ms
```

### ② 账号管理 `/accounts`

- **兑换码**：填码 → 「全部兑换」；可勾选「注册成功后自动兑换」
- 列表：邮箱 / 姓名 / 密码 / **当前套餐** / 时间
- 每行：「兑换」重试一次、「复制」复制账号
- 顶部：搜索、下载账号

### ③ 代理配置 `/proxies`

- 注册相隔（秒）、限流退避（秒）、退避上限（秒）、退避开关
- 代理池：批量粘贴 → 「添加并校验」→ 「全部复检」/「清空」
- 表格列：代理 / 状态 / 成功 / 已用 / 连续限流 / 连续失败 / 最近错误

## 数据文件

全部为纯文本，一行一条，`#` 注释已去除。

| 文件 | 格式 | 说明 |
|---|---|---|
| `注册成功记录.txt` | `邮箱----姓名----密码` | 注册成功的账号 |
| `登录态记录.txt` | `邮箱----Cookie` | 注册时抓到的 `ai_sess` JWT |
| `套餐状态.txt` | `邮箱----套餐----说明` | 兑换后的套餐，如 `Ultra----Ultra plan · 180 days` |
| `proxies.txt` | `网关:端口@用户名:密码` | 代理池，重启后自动加载 |
| `settings.json` | JSON | 间隔、并发、退避、兑换码、自动兑换开关 |

> 这些文件都会随运行生成，**已在 `.gitignore` 中排除**，开源时请勿提交（内含真实账号与 Cookie）。

## 工作流程

```
① 生成随机账号
      ↓
② POST /api/auth/signup        → 200 {"ok":true,"next":"/dashboard"}
      ↓                        同时下发 Set-Cookie: ai_sess=<JWT>
③ 写入 注册成功记录.txt + 登录态记录.txt
      ↓
④ POST /api/promo/redeem {"code":"ALP27"}
      ↓                        → "The Ultra plan is active for 180 days."
⑤ GET /api/keys → quota.plan   → 读取当前套餐
      ↓
⑥ 写入 套餐状态.txt，页面显示套餐
```

关键点：注册成功后响应头里的 `ai_sess` 是一个 JWT（载荷含 `uid` / `email` / `exp`，有效期 30 天），**带着它就能直接访问需要登录的接口**，不必再走一次登录。

## 接口一览

### 目标站点（本项目分析对象）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth/signup` | 注册，body `{email, password, name, ref, promo, captcha}` |
| POST | `/api/auth/login` | 登录，body `{email, password}` |
| POST | `/api/promo/redeem` | 兑换，body `{code}`，返回 `message` / `rewardLabel` |
| GET | `/api/promo` | 兑换历史 |
| GET | `/api/keys` | 密钥列表 + `quota.plan`（套餐名、5h/周额度） |
| GET | `/api/usage` | 近 7 天用量 |
| GET | `/api/referrals` | 邀请码与奖励规则 |

### 本地控制台

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/`、`/register`、`/accounts`、`/proxies` | 三个页面 |
| GET | `/api/stats` | 运行状态、统计、最近日志、代理列表 |
| POST | `/api/start` | 开始，body `{count, concurrency}` |
| POST | `/api/stop` | 停止 |
| POST | `/api/settings` | 保存设置 |
| POST | `/api/logs/clear` | 清空日志（`reset_stats` 可一并重置统计） |
| GET | `/api/accounts` | 账号列表（含套餐，不下发 Cookie） |
| POST | `/api/redeem` | 兑换，body `{code, email?}`；不传 `email` 则全部 |
| POST | `/api/proxies/add`、`/remove`、`/clear`、`/validate` | 代理管理 |
| GET | `/api/download/success`、`/sessions` | 下载账号 / 登录态 |

## 代理格式

只支持 **HTTP 代理**，统一一种写法：

```
网关:端口@用户名:密码      例：1.2.3.4:8080@user:pass
网关:端口                 无认证时，例：127.0.0.1:7897
```

`http://`、`socks5://`、`用户:密码@网关:端口` 等其它写法会被明确拒绝并提示原因。

每个 IP 通常有注册配额，配额耗尽后会被限流：

```json
{"error": "Too many accounts have already been registered from your network."}
```

此时该代理会被记为「连续限流」，达到阈值即自动下线、不再分配——这是正常行为，补充新代理即可。

## 附：一次第三方插件的排查记录（重要）

> 以下是社区中流传的一次排查记录，**不是本项目的功能说明**，仅作背景参考。原图已省略，这里只做文字总结。

**背景**：该站点把「创建 API Key」限制为只能在它的 VS Code 插件里操作，网页端直接调用会返回 `403 desktop_only`。有人于是做了一次排查，过程与结论如下：

**做了什么**

1. 把插件安装包（`.vsix`）下载到临时目录解压，**只读取其中的 JS 静态代码**，用于定位签发 Key 的接口——没有安装、没有启动编辑器、没有执行任何插件代码。
2. 用 `curl` 冒充「编辑器客户端」，走站点自己的浏览器授权流程（`POST /api/vscode/auth/link/start` → 网页确认 → 取 token → `POST /api/vscode/keys`），成功创建了一把 Key。
3. 用这把 Key 调用对话接口 `POST /v1/chat/completions`。

**核查结果**

| 检查项 | 结果 |
|---|---|
| `~/.vscode/extensions` 中的 alpme 扩展 | 0 个 |
| Cursor / Windsurf / VSCodium 等目录 | 不存在 |
| alpme 相关进程 | 无 |
| 官方安装脚本 `alpme.com/install \| sh` | 从未执行 |
| 解压产生的临时文件 | 仅在临时目录，重启即清空 |

→ 结论：**没有向本机安装任何东西，也没有插件进程常驻运行。**

**调用结果：全部 503**

```
POST https://alpme.com/v1/chat/completions → 503
{"error":{"code":"server_overloaded","message":"...high load..."}}
```

- 换成 `deepseek`、`glm`、`gpt`，甚至**一个根本不存在的模型名**，返回的都是一样的 503
- 站点仪表盘的「活动日志」里**连一条请求记录都没有**
- 说明请求在进入它们的路由之前就被统一挡掉了，与 Key、参数无关
- 大概率是上游没有容量，或者促销套餐的额度根本没有接入网关

**关于「挖矿嫌疑」的说明**

- 有人认为这类第三方插件或促销套餐可能夹带**挖矿**等不明行为，因此提醒自行甄别；
- 本次排查**未发现任何挖矿证据**：无相关进程、无持续算力占用、无异常联网，反而是请求被 503 直接拒绝；
- 但同样**无法证伪**——静态读代码只能说明「安装包里写了什么」，不能证明服务端行为；
- 因此：**是否使用该类插件、是否接入该类服务，请自行判断与甄别。** 若在意安全，至少做到：不要把插件装进主力开发环境、不要在生产机器上运行、用独立虚拟机/容器隔离、持续观察 CPU/GPU 与网络出站。

**这段记录对你有用的两个结论**

1. `403 desktop_only` 说明「网页端不许建 Key」是产品设计，绕过它属于违反服务条款，账号有被封风险。
2. `503 server_overloaded` 说明「页面显示 Ultra」不代表「API 真的能用」——套餐状态与实际可用性是两件事。

## 已知限制

- 接口与字段绑定具体站点，站点改版即失效，不保证可用
- 单 IP 有注册配额，无代理时很快被限流，这是服务端策略，脚本无法也不应绕过
- 兑换码有使用次数限制，同一账号重复兑换会返回 `This code has already been used.`
- 代理只支持 HTTP；`socks5` 会被拒绝
- 控制台无鉴权，只监听 `127.0.0.1`，请勿改成 `0.0.0.0` 对外暴露
- 所有数据以明文保存在本地，请自行做好隔离
